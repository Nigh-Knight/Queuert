## Key Technical Decisions (This Session)

1. **Flow Order for Service Users:**
   - Changed from QR-first to Registration-first
   - Rationale: Users should provide their info before scanning volunteer/admin QR
   - Correct flow: RegistrationFormScreen → QRCodeScannerScreen → LaundryStatusScreen

2. **Admin Verification UX:**
   - Single verification screen (removed duplicate bottom sheet)
   - No back button (admin must verify to proceed)
   - Top padding for camera notch clearance
   - Rationale: Cleaner UX, prevents confusion from duplicate inputs

3. **Volunteer Navigation:**
   - Direct route to /(volunteer) on button press
   - Was logging "coming in future phase" instead
   - Rationale: Infrastructure was already built, just needed routing fix

4. **Existing UI Component Reuse:**
   - Service user flow uses components from components/provider/screens/
   - RegistrationFormScreen, QRCodeScannerScreen, LaundryStatusScreen
   - Rationale: UI was already built, just needed proper routing and backend wiring

5. **Backend Integration Pattern:**
   - All flows wire to Convex mutations from Plan 02-01
   - validateVolunteerQR, validateSessionQR, registerServiceUser, verifyAdminCode
   - Session saved to AsyncStorage via SessionStorage utility
   - Rationale: Consistent auth pattern across all three roles
